# CS2: сбор группы ботов в одно лобби по коду (lobby ID)

**Дата:** 2026-05-30
**Статус:** Design (утверждён, ожидает реализации)
**Фаза проекта:** 3C (Private Lobby) — подэтап «сбор своих аккаунтов в одно лобби»

## Цель

Собрать всех ботов фарм-группы в **одно приватное лобби CS2** по lobby ID, **без добавления в друзья**. Это шаг 1 — отработка механики сбора. Запускается из UI одной кнопкой.

## Вне объёма (отдельные фазы позже)

- Matchmaking / поиск матчей
- Сбор лобби по 2 бота и queue sync (2v2 друг против друга)
- Round-robin убийства, движение/стрельба в лобби
- Добавление аккаунтов в друзья

## Контекст

- Боты запускаются в Sandboxie-боксах `CS2Bot_<accountId>`, последовательный авто-вход в Steam уже работает (`CS2Launcher`, `SandboxSteamGuard`).
- Фарм-группы (2–4 аккаунта) и окно отслеживания уже есть (`GroupManager`, `FarmGroups.jsx`, `TrackingWindow.jsx`).
- Запуск группы последовательный (`groups:start`): следующий бот стартует после полного входа предыдущего.
- «Короткого внутриигрового кода» в CS2 (как в Among Us) нет. Есть **lobby ID** (64-бит), консольная команда `connect_lobby <id>`, ссылка `steam://joinlobby`. Дизайн строится вокруг lobby ID.

## Выбранный подход

**Вариант 1 — Netconsole TCP (`-netconport`) + `connect_lobby`** (основной).
Каждый CS2 запускается с `-netconport <port>` — игра открывает локальный TCP-консольный порт. Панель подключается к нему, шлёт консольные команды и читает вывод: хост создаёт лобби → читаем lobby ID → остальным ботам шлём `connect_lobby <id>`.

**Фолбэк — Вариант 2** (если netconport не работает в Sandboxie или не поддерживается CS2): внутриигровая консоль через нашу рабочую систему фокус+`keybd_event` (та же, что для входа Steam) + чтение lobby ID из `console.log` (флаг `-condebug`).

**Отклонено — Вариант 3 (Steam GC / node-globaloffensive):** GC-лобби рассинхронизировано с игровым клиентом, аккаунт уже залогинен в игре — не даёт реальные клиенты в одном лобби.

## Архитектура

| Компонент | Роль |
|---|---|
| `CS2NetConsole.js` (новый, main/modules) | TCP-клиент к netconsole CS2: `connect(port)`, `send(cmd)`, чтение вывода с парсингом ответов |
| `LobbyManager.js` (новый, main/modules) | Координатор сбора: выбрать хоста, создать лобби, прочитать ID, разослать `connect_lobby`, отслеживать результат |
| `CS2Launcher.js` (правка) | Добавить флаг `-netconport <NETCON_BASE + accountId>` при запуске CS2 |
| `ipc.js` + `preload/index.js` | Хендлер `lobby:gather(groupId)` + проброс в `window.api.lobby.gather` |
| `FarmGroups.jsx` | Кнопка «Собрать в лобби» на карточке группы |
| `TrackingWindow.jsx` | Кнопка «Собрать в лобби» + новый статус `in_lobby` в бейджах |

**Порты netconsole:** `NETCON_BASE (29100) + accountId` — уникальный порт на каждый бокс, чтобы панель адресовала нужный экземпляр CS2.

## Фаза 0 — Спайк (проверка, ПЕРВЫМ делом)

Реализация основной логики начинается только после успешного спайка.

1. Запустить один CS2 в боксе с `-netconport 29100`.
2. Из Node подключиться TCP к netconsole бокса, послать пробную команду (`echo test` / `status`), убедиться что ответ приходит. **Главная проверка** — пробивает ли Sandboxie сеть до этого порта (сетевая изоляция бокса).
3. Найти/подтвердить команды: создание приватного лобби и чтение его **lobby ID** (через вывод консоли или `status`). Самый неизвестный момент.
4. Зафиксировать результат. Если netconport заблокирован/не поддерживается → переключиться на Вариант 2.

**Критерий успеха спайка:** панель программно получает ответ от консоли CS2 в боксе И известны команды создания лобби + чтения lobby ID.

## Рабочий поток (после успешного спайка)

```
1. Группа запущена (существующая последовательная логика), все боты в главном меню CS2
2. LobbyManager выбирает ХОСТА (первый аккаунт группы по position)
3. Хосту через netconsole → команда создания приватного лобби
4. Читаем lobby ID хоста из вывода netconsole
5. Каждому ОСТАЛЬНОМУ боту → connect_lobby <lobbyID> через его netconsole
6. Проверяем, что все зашли (через GSI или повторный опрос netconsole)
7. Статусы → окно отслеживания (статус in_lobby)
```

## UI

- Кнопка **«Собрать в лобби»** на карточке группы (`FarmGroups.jsx`) — активна только когда все боты группы в главном меню (готовы: `steam_running` / `cs2_lobby`).
- Дублирующая кнопка в окне отслеживания (`TrackingWindow.jsx`).
- Новый статус **`in_lobby`** («В общем лобби») в бейджах статусов (Accounts.jsx, TrackingWindow.jsx).

## Обработка ошибок

| Ситуация | Реакция |
|---|---|
| netconsole не подключается к боксу | статус бота `error`, сообщение «нет связи с консолью CS2», сбор прерывается |
| lobby ID не прочитан у хоста | `error` у хоста, остальных не трогаем |
| `connect_lobby` отправлен, но бот не зашёл (таймаут) | статус `error` у конкретного бота, остальные остаются в лобби |
| бот ещё не в меню | кнопка «Собрать в лобби» заблокирована (как очередь у перезапуска) |

## Тестирование

- Спайк сам по себе — первый тест (netconsole отвечает, команды найдены).
- Ручной: группа из 2 ботов → «Собрать в лобби» → оба в одном лобби (визуально в CS2 + статус `in_lobby`).
- Конкретный план тестирования дописывается после реализации.
