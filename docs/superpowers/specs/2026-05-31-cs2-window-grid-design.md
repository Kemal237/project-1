# Сетка-раскладка окон CS2 (ReWindow) — Design

**Дата:** 2026-05-31
**Статус:** Утверждён, готов к написанию плана

## Цель

Аккуратно раскладывать окна запущенных через панель экземпляров CS2 по сетке на экране, чтобы оператор видел все окна без наложений. Референс — окно-раскладка в проекте 7VBPanel.

## Контекст и ограничения

- CS2 запускается через `CS2Launcher` в Sandboxie, в **windowed-режиме 640×480** (`-windowed -w 640 -h 480`, см. `CS2_FLAGS` в `src/main/modules/CS2Launcher.js`).
- PID каждого окна уже хранится: `cs2Launcher._active` (accountId → `{ boxName, cs2Pid, ... }`).
- В `BotAutomation.js` уже отлажен паттерн Win32-interop через временные PowerShell-скрипты (`Add-Type`, `EnumWindows`, поиск HWND по PID).
- CS2 на Source 2 поддерживает launch-флаги `-x N` и `-y N` — смещение окна от левого-верхнего угла рабочего стола в пикселях ([Valve Dev Wiki](https://developer.valvesoftware.com/wiki/Command_line_options_(Source_2))).
- Размер окон **не меняется** — остаётся 640×480 (CS2 рендерит в этом разрешении; растяжка окна дала бы мыло/чёрные поля). Раскладка только перемещает окна.

## Решения (утверждены пользователем)

| Вопрос | Решение |
|---|---|
| Конфигурация сетки | Авто (`cols = ceil(sqrt(n))`) + ручной override числа столбцов |
| Когда раскладывать | При запуске CS2 через `-x/-y` (основной путь) + кнопка «Разложить окна» (коррекция) |
| Размер окон | Оставить 640×480, только перемещать |
| Монитор | Основной монитор (рабочая область) |

## Архитектура

Два механизма позиционирования, оба используют один источник истины — `WindowGrid.computeGrid()`:

### 1. Позиция при запуске (`-x/-y`) — основной путь

Когда бот стартует, панель вычисляет его слот и добавляет `-x N -y N` к флагам запуска. Окно CS2 рождается сразу в своей ячейке — без прыжка/мигания после запуска.

- **Слот = следующая свободная ячейка** по числу уже запущенных ботов на момент старта (число записей в `cs2Launcher._active` с `cs2Pid`).
- **Ширина сетки (столбцы)** на момент запуска: ручное значение из Settings (`window_grid_cols`), если задано (>0); иначе фиксированный дефолт **2** (две колонки 640-окон ≈ 1312px влезают в типовой 1920-экран). Фиксированная ширина → окна не «съезжают» при поочерёдном старте.
- Заменяет необходимость в «авто-SetWindowPos после запуска» — окно и так появляется на месте.

### 2. Кнопка «Разложить окна» (SetWindowPos) — коррекция

Нужна, потому что:
- Боты запускаются по одному → авто-сетка (2×2 vs 3×3) зависит от финального числа; кнопка пересчитывает идеальную сетку под фактическое число запущенных окон.
- Окно сдвинули вручную / краш-перезапуск / слот-коллизия → кнопка приводит всё в порядок.

Перемещает уже живые окна через `SetWindowPos` с флагом `SWP_NOSIZE` (размер 640×480 сохраняется).

## Компоненты

### `src/main/modules/WindowGrid.js` (новый модуль)

Одна ответственность — раскладка окон CS2. Чистая математика отделена от Win32-сайд-эффектов (паттерн как `FriendPairs.js`).

- **`computeGrid(count, screenW, screenH, opts)`** — чистая функция.
  - Входы: `count` (число окон), `screenW`/`screenH` (рабочая область основного монитора), `opts` — `{ cols?: number, winW?: number, winH?: number, gap?: number }`.
  - Логика: если `opts.cols` задан — берём его; иначе `cols = Math.ceil(Math.sqrt(count))`. `rows = Math.ceil(count / cols)`. Ячейка = `winW × winH` + `gap`.
  - Константы по умолчанию: `winW = 656`, `winH = 519` (640×480 client + стандартная рамка Windows ≈ 8px по бокам + ~31px title bar), `gap = 0`. Значения — module-level константы, можно скорректировать на этапе ручного теста, если рамка отличается.
  - Выход: массив из `count` объектов `{ x, y }` — координаты левого-верхнего угла каждого окна, слева-направо, сверху-вниз, старт от (0,0) рабочей области.
  - Без сайд-эффектов → юнит-тестируется.

- **`slotForLaunch(accountId)`** — возвращает `{ x, y }` для запускающегося бота.
  - Слот-индекс = число уже запущенных CS2 (записи в `cs2Launcher._active` с `cs2Pid`).
  - Столбцы для launch-времени: ручное значение из Settings (`window_grid_cols`), если задано (>0); иначе фиксированный дефолт **2**. Фиксированная ширина → окна не «съезжают» при поочерёдном старте.
  - Зовёт `computeGrid(slotIndex + 1, screenW, screenH, { cols })` и берёт последнюю (по слот-индексу) ячейку.

- **`arrange(opts)`** — кнопка/коррекция.
  - Собирает запущенные `(accountId, cs2Pid)` из `cs2Launcher._active`.
  - Берёт размер рабочей области основного монитора (через Electron `screen.getPrimaryDisplay().workAreaSize` либо PowerShell).
  - Зовёт `computeGrid(count, ...)`, строит карту `pid → {x, y}`.
  - Одним вызовом PowerShell-скрипта двигает все окна.

### PowerShell-скрипт `arrange-windows.ps1`

- Принимает список троек `pid:x:y` (одна строка-параметр или массив).
- Через `EnumWindows` находит главное видимое окно каждого PID.
- `SetWindowPos(hWnd, IntPtr.Zero, x, y, 0, 0, SWP_NOSIZE | SWP_NOZORDER)`.
- Один спавн PowerShell на всю раскладку (не N).
- Пишется в ту же временную папку, что и скрипты BotAutomation (`%TEMP%/cs2farmpanel-ps`).

### `CS2Launcher.js` — интеграция launch-флагов

- В точке формирования флагов запуска CS2 (около строки 170, вызов `_spawnInBox(... [..., ...CS2_FLAGS])`) добавить динамические `-x N -y N`, полученные из `WindowGrid.slotForLaunch(accountId)`.
- `CS2_FLAGS` остаётся статичной; флаги позиции добавляются отдельно на каждый запуск.
- Учесть настройку: если авто-раскладка выключена — `-x/-y` не добавляются.

### IPC и UI

- IPC-хендлер `windows:arrangeGrid` → `WindowGrid.arrange(opts)` (opts может содержать ручное число столбцов).
- Кнопка «Разложить окна» на странице FarmGroups (там управление группами ботов).
- Поле/инпут «Столбцы» рядом с кнопкой (пусто = авто).
- Тумблер «Авто-раскладка окон при запуске» в Settings (управляет добавлением `-x/-y` при старте).

## Поток данных

```
Запуск бота:
  CS2Launcher.start(accountId)
    → WindowGrid.slotForLaunch(accountId) → {x, y}
    → флаги: [...CS2_FLAGS, '-x', x, '-y', y]
    → _spawnInBox(...) → окно CS2 рождается в ячейке

Кнопка «Разложить окна»:
  UI → IPC windows:arrangeGrid(opts)
    → WindowGrid.arrange(opts)
      → собрать pid'ы из _active
      → computeGrid(count, screenW, screenH, opts) → [{x,y}, ...]
      → arrange-windows.ps1 (pid:x:y ...) → SetWindowPos каждого окна
```

## Обработка ошибок

- Нет запущенных окон → `arrange()` ничего не делает, возвращает `{ moved: 0 }`.
- HWND по PID не найден (окно ещё грузится) → пропускаем это окно, остальные расставляем.
- Сетка шире/выше экрана (много окон при 640×480) → крайние окна уходят за край экрана. Приемлемо для MVP; не усложняем.
- Слот-коллизия при запуске (бот остановлен, новый занял индекс существующего) → возможна; исправляется кнопкой «Разложить окна». Не блокирует MVP.
- PowerShell-ошибка → логируем, не роняем приложение.

## Тестирование (инкрементально)

1. **`computeGrid` + юнит-тесты** — `scripts/test-window-grid.mjs` (паттерн `scripts/test-friend-pairs.mjs`, запуск `node`):
   - 4 окна, авто → 2×2, проверить 4 координаты (углы ячеек).
   - 6 окон, авто → 3×2.
   - override `cols=3` при 4 окнах → 3 в первом ряду, 1 во втором.
   - 1 окно → (0,0).
   - 0 окон → пустой массив.
2. **`-x/-y` при запуске** — запустить бота через панель, глазами проверить, что окно появилось в своей ячейке без прыжка.
3. **Кнопка + PS SetWindowPos** — запустить 2-4 бота, нажать «Разложить окна», проверить ре-раскладку живых окон в идеальную сетку.
4. **Настройки** — проверить ручной override столбцов и тумблер авто-раскладки (выключен → окна не позиционируются при запуске).

## Вне области (YAGNI)

- Мультимониторная раскладка (только основной монитор).
- Изменение размера окон / borderless.
- Запоминание индивидуальных позиций окон между сессиями.
- Drag-and-drop расстановка в UI.
