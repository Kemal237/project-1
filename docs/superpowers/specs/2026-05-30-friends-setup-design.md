# Этап 1 — Невидимая настройка дружбы группы через steam-user

**Дата:** 2026-05-30
**Статус:** Design (утверждён, ожидает плана)
**Часть пайплайна:** XP-фарм через Wingman queue-sync. Это **Этап 1** (фундамент). Полный пайплайн и его развороты — в `2026-05-30-cs2-lobby-gather-design.md` (раздел «Результаты спайка») и в памяти проекта.

## Цель

Сделать все аккаунты одной фарм-группы **взаимными друзьями Steam**, **невидимо** (без экранной автоматизации), одной кнопкой. Это разовая настройка — без неё невозможен инвайт в пати (Этап 2) и queue-sync.

## Контекст и почему именно так

- Дружба нужна, потому что инвайт в CS2-пати требует, чтобы аккаунты были друзьями.
- Делаем **через код, а не через UI** (явное требование пользователя): в проекте уже есть `steam-user` ^5.3.0, `steam-totp`, `steamcommunity` и рабочий логин-флоу (`SteamWorker` + `SteamAuth.login()`, фича Farm Start).
- `steam-user`: `client.addFriend(steamID64)` отправляет заявку; если встречная заявка уже есть — Steam **сразу делает друзьями** (auto-accept). Тот же вызов служит и приёмом входящей заявки.
- **Код дружбы не нужен** для code-пути: `addFriend` принимает `steamID64`, который у нас уже есть (его сохраняет `SteamWorker` при логине). (Для справки: friend code = steamID64 − 76561197960265728.)

## Вне объёма (другие этапы)

- Сбор в пати, инвайт в пати (Этап 2). Настройка/старт поиска, детект матча, контроль матча (Этапы 3–6).
- Авто-определение «limited»-статуса через сторонние сервисы (в этом этапе — обрабатываем по факту ошибки `addFriend`, не запрашиваем извне).

## Ограничения Steam (важно для алгоритма)

- **Limited-аккаунт** (потрачено < $5 за историю) **не может ОТПРАВЛЯТЬ** заявки в друзья, но **может ПРИНИМАТЬ** входящие. На уровне `steam-user` это значит: `addFriend(target)` от limited-аккаунта, когда **нет** встречной заявки, отклоняется сервером; но `addFriend(target)`, когда target **уже отправил** заявку, проходит как приём.
- Следствие: в паре {A,B} нужно, чтобы **сначала отправил non-limited**, затем второй вызвал `addFriend` (приём/взаимность). Если оба limited — подружить нельзя.
- **Конфликт сессий:** один аккаунт не может одновременно держать две клиентские сессии Steam. Поэтому дружба выполняется только когда аккаунт **полностью idle** — не запущен в CS2/боксовом Steam (`cs2Launcher.isRunning(accountId)`) И не имеет активной Farm-сессии (`SteamWorker` через workerManager). Если аккаунт уже в активной Farm-сессии — либо переиспользовать её клиент (опционально, только для Prime), либо требовать остановки; в этом этапе для простоты требуем idle.

## Архитектура

| Компонент | Роль |
|---|---|
| `FriendSession.js` (новый, main/modules) | Лёгкая одноразовая steam-user сессия одного аккаунта: логин через `SteamAuth.login()` (прокси+Guard), **без** GC/Prime/gamesPlayed (не отключается на non-Prime). Методы: `connect()`, `addFriendBySteamId(id64)`, `getRelationship(id64)`, события `friended`/`error`, `close()`. |
| `FriendManager.js` (новый, main/modules) | Координатор: `ensureGroupFriends(groupId, onProgress)`. Берёт аккаунты группы и их steamID64, считает недостающие пары, поднимает `FriendSession` на нужных аккаунтах, шлёт `addFriend`, отслеживает результат, репортит прогресс, гасит сессии. Чистая функция расчёта пар — отдельно (для юнит-теста). |
| `ipc.js` (правка) | Хендлер `friends:ensureGroup(groupId)` → `FriendManager.ensureGroupFriends` с прокидкой прогресса в renderer. |
| `preload/index.js` (правка) | `window.api.groups.ensureFriends(groupId)`. |
| `FarmGroups.jsx` (правка) | Кнопка «Подружить группу» на карточке группы + индикация прогресса/итога. |

### Почему отдельный `FriendSession`, а не `SteamWorker`

`SteamWorker._handleLicenses` при отсутствии Prime делает `logOff` и обнуляет клиента (`no_prime`). Для дружбы сессия должна жить независимо от Prime и не тащить GC/драгоценный keepalive. Поэтому — отдельный лёгкий класс, переиспользующий только `SteamAuth.login()` (общий логин-флоу: прокси, refreshToken, Steam Guard через shared_secret/steam-totp).

## Алгоритм `ensureGroupFriends(groupId, onProgress)`

```
1. group = groupManager.get(groupId); если аккаунтов < 2 → { ok:false, error:'нужно ≥2 аккаунта' }
2. Проверка: ни один аккаунт группы не запущен в CS2 (cs2Launcher.isRunning). Иначе → { ok:false, error:'останови CS2 у аккаунтов группы' }
3. Убедиться, что у всех есть steamID64. У кого нет — пометить «нужен первый вход» (заполнится при connect FriendSession).
4. Для каждого аккаунта поднять FriendSession (последовательно или с ограниченной параллельностью), залогиниться.
   - onProgress(accountId, 'connecting'|'error', msg)
5. Полный граф: для каждой неупорядоченной пары {A,B}, ещё не друзей:
   - вызвать A.addFriendBySteamId(B.steamId) и B.addFriendBySteamId(A.steamId)
   - тот, кто non-limited, создаёт заявку; второй вызов завершает дружбу (взаимность/приём)
   - если оба вызова отклонены (оба limited) → onProgress по обоим 'error' «оба аккаунта limited — дружба невозможна»
6. Подождать события дружбы / опросить getRelationship до Friend (таймаут на пару).
7. Закрыть все сессии. Вернуть { ok, friended:[...], failed:[{id,reason}] }
```

`onProgress(accountId, status, message)` — пробрасывается в renderer (как существующие statusChange), статусы: `connecting`, `friending`, `friended`, `error`.

## Обработка ошибок

| Ситуация | Реакция |
|---|---|
| Аккаунт группы запущен в CS2 | Прервать весь процесс, попросить остановить CS2 (конфликт сессий) |
| Нет прокси у аккаунта | `error` по аккаунту, сообщение «прокси обязателен» (как в SteamWorker) |
| Steam Guard не вводится / таймаут | `error` по аккаунту, остальные продолжаются |
| `addFriend` отклонён у обоих в паре (оба limited) | `error` по паре, остальные пары не трогаем |
| Уже друзья | Пропуск (идемпотентность), `friended` |
| Логин fatal (бан/неверный пароль) | `error` по аккаунту, продолжаем остальных |

## Тестирование

- **Юнит (TDD):** чистая функция расчёта пар `computeFriendPairs(accounts)` — какие пары нужно подружить (исключая уже-друзей), порядок «non-limited первым». Без сети.
- **Ручной:** реальный прогон «Подружить группу» на группе из 2 аккаунтов (не запущенных в CS2) → проверить, что в Steam они стали друзьями. Затем 3–4 аккаунта (вкл. подозрение на limited).

## Открытые вопросы (проверяются при ручном тесте)

1. Поведение `addFriend` у limited-аккаунта в `steam-user` — отдаёт ли ошибку, по которой можно отличить «limited/нельзя отправить» от прочих. (Если событие/ошибка неинформативна — определяем limited по факту: заявка не привела к дружбе в таймаут, при том что встречная отправлена.)
2. Достаточно ли «обе стороны вызвали addFriend» для мгновенной дружбы non-limited пар, или нужен явный приём (setFriendRelationship). Уточняется на ручном тесте; алгоритм уже закладывает оба вызова.
