## 🟡 Phase 3 — Реальный фарм CS2 кейсов

**Цель:** Бот не просто держит онлайн, а играет в матчи и получает дропы.

Разбит на 5 фаз: **3A (детект дропов)** → **3B (запуск игры)** → **3C (лобби и матч)** → **3D (гуманизация)** → **3E (приоритет дропов)** → опционально **3F (HWID spoof)**.

### ✅ Phase 3A — GC Drop Detection (DONE)

[spec](superpowers/specs/2026-05-15-phase3a-gc-drop-detection-design.md) · [plan](superpowers/plans/2026-05-15-phase3a-gc-drop-detection.md)

- **CS2GCClient.js** — подключение к Game Coordinator (CSGO_Client protocol)
- Real-time детект `CMsgClientItemDrops`, парсинг item type
- События `drop` / `xpUpdate` в SteamWorker
- Запись дропов в БД с типом и временем
- Auto reset weekly drops counter (каждую среду UTC)

### 🔄 Phase 3B — Запуск игры (изоляция + Steam + CS2) — CURRENT

**Цель:** Запустить Steam от изолированного пользователя, поднять CS2 в окне, дойти до главного меню. БЕЗ матчей, БЕЗ команд внутри игры. Только стабильный запуск.

| Подэтап | Описание | Спек | Статус |
|---|---|---|---|
| **3B-1** | **Windows User Accounts изоляция** (replace Sandboxie) | [спек](superpowers/specs/2026-05-17-windows-user-accounts-isolation-design.md) | 🔄 **СЕЙЧАС** |
| 3B-2 | Stabilization launcher: handle errors, parallel boots, retry | Pending | После 3B-1 |
| 3B-3 | Profile warmup на createUser (быстрый первый launch) | Pending | По необходимости |

**Что входит в 3B-1:**
- `UserAccountManager.js` — создание/удаление Windows-пользователей (`net user`)
- `ProcessLauncher.js` — запуск exe от другого юзера через PowerShell `Start-Process -Credential -LoadUserProfile`
- `CS2Launcher.js` rewrite — без Sandboxie, через User Accounts
- 1:1 mapping: каждый Steam-аккаунт → свой `cs2botN`
- БД миграция: wipe старых данных, добавить колонки `windows_user`, `windows_password_enc`

**Что НЕ входит в 3B:**
- ❌ Никакого `bot_add` / private lobby
- ❌ Никакого movement / клавиатуры в CS2
- ❌ Никакого автовыбора дропов
- ❌ Никакого HWID spoofing

3B-2 и 3B-3 — это **стабилизация запуска** после 3B-1, если выявятся проблемы при тестировании (например медленное создание профиля на первом запуске или конфликты при параллельном бутинге 5+ ботов).

## Принципы работы

1. **YAGNI** — каждая фаза делает минимум для цели. Усложнения — позже.
2. **Spec → Plan → Implementation** — каждая фаза проходит цикл brainstorming/spec/plan/execute через superpowers.
3. **Одна фаза = один спек** — не миксуем 3B-1 с 3C-1 в одном спеке.
4. **Тестирование сразу** — каждая фаза проверяется на реальных аккаунтах сразу после реализации.
5. **Готовая к продаже** — продукт. Каждая фаза должна оставлять панель в рабочем состоянии (не "разломанный мастер" между фазами).
